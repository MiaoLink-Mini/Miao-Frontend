# 当前三层接入状态

2026-09-06：`LiveGateway`、`wire.js` 与 Runtime 已接入 `weagent/1`。当前默认 live + 本机开发身份；登录/配对/会话/审批/提问/取消/历史与断线恢复已完成跨层 fixture 验证。详见 [本轮 Review、修复与验收边界](integration-review.md)。

协议唯一来源为 `../Miao-Backend/contracts/protocol.schema.json`。`npm run sync:contract` 生成小程序无运行依赖的协议数据，`npm run build` 校验漂移与回归。真实微信凭据、HTTPS/WSS 合法域名和付费模型响应尚未验收。

## 本机运行

- Gateway：按 `../Miao-Backend/docs/running.md` 启动。保留当前已有服务，不重启或覆盖其他 Agent 的进程。
- 应用层：按 `../WeAgent-Node/README.md` 配置并启动 Daemon；在小程序配对页输入其一次性配对码，核对指纹后确认。不要将私钥、凭据和 stateDir 加入源码。
- 前端：开发者工具导入本工程。`miniprogram/config.js` 默认使用本机 18080 与开发身份 owner；连接失败不会回退 FakeGateway。
- 独立回归：`npm run test:integration` 使用另一个端口和临时数据库，原生模型接口为 fixture，不触发付费模型请求。

## 实现方式

1. 从确认的 schema 生成独立 `protocol/` 层；严格区分外部原生协议、Gateway 统一协议和前端视图模型。
2. 实现 `LiveGateway` 及认证／网络服务。当前构造函数会明确抛出 `LIVE_NOT_CONFIGURED`；仅改 `config.mode` 不会悄悄进入模拟模式。
3. 页面继续通过 Runtime 读取授权视图和提交动作。不得在组件中创建独立 WebSocket 或按 Agent 品牌分叉业务。
4. 微信连接需使用经过实际环境核验的 SocketTask 生命周期；应用持有连接，页面只订阅业务。当前 Fake Gateway 的订阅不等同于已实现真实 WSS。
5. 先认证与确认授权，再建立带覆盖位置的快照／历史基线，补齐持久事件并衔接实时流；补历史期间缓冲实时事件。不能只有游标没有正文。
6. 服务端接收、主机送达、原生接受、实际执行终态分别映射；超时先查询操作结果，不能重新执行相同副作用。前端操作标识只用于请求归并，不能替代服务器鉴权。
7. 实际发送、审批、问题、取消、模型、还原等动作都需重新校验资源、轮次、请求有效期及能力。前端禁用按钮不能替代后端校验。
8. 根据运行时 metadata 更新能力记录；新能力先补充 target version、运行模式、数据来源、映射、验证结果，再启用入口。

## 明确保留的限制

- Fake Gateway 采用本次运行内的完整事件日志，未实现服务端保留期、快照压缩、分页网络接口、指数退避或真实鉴权刷新。
- 时间线按 24 张卡片增量显示，Diff 按 80 行展开。真实长历史需要后端分页与分块更新，当前演示不声称可处理任意规模日志。
- 正文目前采用可选择的纯文本；代码、表格与 Markdown 的专业渲染仍属 H03 待接入。
- 仅展示演示用量；实际币种、成本来源、额度与上下文占用未提供时显示缺失，不显示零。
- 文件查看仅是选定 Diff 的只读演示片段。没有任意文件路径输入、文件编辑器、终端、市场安装、自动化调度或计费写操作。
- 图片、URL 打开、微信订阅消息等能力还需实际微信平台配置和版本核验。
