# Monochrome / 视觉改版

## 参考与范围

参考 [tetsuo-ai/agenc-android](https://github.com/tetsuo-ai/agenc-android/tree/6adc090) 的 `ui/Theme.kt`、`ui/screens/MainDesign.kt` 和 `HomeScreen.kt`：始终深色的画布、灰阶表面、细边框、编号分区、等宽数字和高对比主要操作。

这是原生微信小程序的独立实现，保留 WeAgent 名称、总览／会话／待处理／我的四个入口以及现有演示流程；不引入 Android、钱包或 Ledger 功能，也不复制参考项目的品牌标志。

## 视觉规范

| 用途 | 颜色 |
| --- | --- |
| 画布／导航栏 | `#000000` |
| 卡片／底部导航 | `#090909` |
| 次级表面／输入框 | `#111111` / `#181817` |
| 边框 | `#2a2a28` |
| 主文字／主要按钮 | `#f4f4f1` |
| 次文字／辅助文字 | `#a7a7a1` / `#858580` |

绿、蓝、琥珀和红色主要表示在线／完成、运行、等待处理和错误状态，并保留中文状态标签，不只靠颜色传达信息。会话详情进一步采用低饱和终端风格：近黑画布、等宽排版、细分隔线、`❯` 输入提示符、内联工具输出；不再使用浅色聊天气泡和堆叠圆角卡片。用户消息用左侧标线区分，助手显示品牌 SVG；复制／引用收纳在消息菜单中，也可长按消息展开。审批／问题保留醒目的审阅入口，不改变提交语义。

- 全局样式：`miniprogram/app.wxss`，各页面和共享组件只补充布局差异。
- 登录、工作台、会话、待处理、我的、配对、创建、聊天、审批与只读详情使用统一视觉。
- 首页主要操作前移，保留设备、最近会话和项目入口。
- WXML 的单行文案不保留格式化产生的首尾换行，避免徽标、筛选项和行间距意外变高；正文中有意保留的换行不变。
- 显式覆盖 `style: v2` 的原生按钮宽度，主要操作铺满内容区，小按钮保持自适应。

## 图标

Claude、Pi、Codex 使用本地品牌 SVG；来源、调整和许可见 [Agent 品牌图标](agent-icons.md)。未知 Agent 使用原创终端图标。此映射仅用于显示，不决定 Agent 能力。

`scripts/generate-icons.js` 中的原创几何线段为源数据，生成 `assets/vectors/*.svg` 和 72×72 RGBA PNG。原生 tabBar 直接引用本地 PNG，不依赖图标字体或网络。

```sh
npm run icons
npm run build
```

测试检查图标可重复生成、正确颜色、非透明像素、透明背景、PNG 结构和尺寸。结构检查同时检查页面使用的 `/assets/` 图片是否存在。

原图标文件并未损坏；本机模拟器在完整重载后恢复显示。修改导航配置或资源后，应完整编译，而不只依赖已经缓存的 tab 页热更新。本次未采用运行时反复设置 tabBar 或自定义导航来绕过缓存。

## 模拟器验证

`npm run test:simulator` 使用官方 `miniprogram-automator` 连接已开启自动化的本地开发者工具，默认端口 9420；不属于普通 `build` 的依赖。可在工程外安装该 SDK，并通过 `WECHAT_AUTOMATOR_PATH` 指定其模块目录。`WECHAT_AUTOMATION_ENDPOINT` 可覆盖连接地址。

脚本仅允许 Fake Gateway：检查 PNG 图标解码、原生导航配色、主要按钮宽度、紧凑文案布局、草稿输入／禁用状态、搜索空状态和筛选；分别截图 Codex／Claude／Pi 的 SVG 和终端会话，验证消息菜单、引用到输入、工具输出展开／收起及大字号偏好。SVG 通过 `<image>` 渲染及截图检查，PNG 另以 `wx.getImageInfo` 验证。不会提交任务、批准请求或修改持久化偏好；临时草稿和内存字号偏好在检查后恢复。截图和报告保存至已忽略的 `test-results/appearance/`。

## `/` 命令预测

会话输入框在开头输入 `/` 会弹出候选，支持英文前缀和中文关键词（如 `/pl`、`/计划`）。点击候选只补全输入，点击“运行”才打开对应页面；不自动提交 Agent 任务。也可以点击输入框上方的 `/ 命令`。该入口不会覆盖已有普通文本草稿。

目前提供小程序**本地、只读**快捷操作：`/help`、`/plan`、`/diff`、`/usage`、`/queue`、`/latest`。计划、差异、用量及排队入口按会话能力元数据显示，不按品牌推断。它们不是 Claude／Pi／Codex 的原生命令目录；`/model`、`/compact` 等原生操作仍需主机提供并验证后接入。

正文、URL、文件路径或多行文本不触发补全；不匹配的独立 slash 输入不会自动发送，用户可显式选择“作为文本”后按普通消息发送。关闭候选不会把已识别的命令悄悄改成普通消息。候选最大高度随键盘事件收缩，列表可滚动。

`npm run test:slash` 单独验证候选、筛选、点击补全、本地计划页路由、原文模式、草稿保护和模拟键盘几何；连接方式与 `test:simulator` 相同，检查后恢复原草稿。键盘几何使用模拟事件，不等同于真机输入法测试。

真机键盘、横屏、跨基础库版本和真实后端仍需要单独验收。

## 处理请求：完整卡片与固定操作区

`pages/request` 按提供的截图恢复黑白灰卡片样式：大标题、完整设备／项目／Agent／会话明细卡，以及独立的问题／补充说明圆角卡片。Agent 保留已有本地 SVG；不再使用偏绿紧凑样式或将上下文藏进弹窗。

页面本身禁用滚动，正文使用有明确 flex 高度的原生 `scroll-view` 独立滑动。提交／审批按钮位于其外部、不参与滚动，始终占据底部视口空间并保留安全区。长上下文和任意多字段表单不再强行压成一屏。键盘高度事件缩短内容视口并滚动至当前输入字段，不隐藏上下文、不压缩卡片；主要操作保持在键盘上方。

`npm run test:request` 检查正文实际滚动、末尾字段可达、按钮位置不变，以及正常／大字号、八字段长表单、单选与文字输入、模拟键盘避让和审批范围。不会提交回答或审批，结束后恢复临时表单、答案和字号偏好。截图 `request-card-top.png`、`request-card-scrolled.png`、`request-card-keyboard.png`、`approval-card-scrolled.png` 和报告保存在已忽略的 `test-results/appearance/`。此改动只针对“处理请求”详情页，没有合并待办列表，也没有改变会话 CLI 样式。
